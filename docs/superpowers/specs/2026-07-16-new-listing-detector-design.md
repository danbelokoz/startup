# Детектор новых листингов + пересборка каталога из архива

Дата: 2026-07-16 · Статус: принят

## Задача

TrustMRR (июль 2026) обрезал standard-ключ: 10 req/min, `limit` ≤ 10 и — главное —
**пагинация отдаёт только первые 200 стартапов** любой выборки. Каталог из 8401
стартапа через API больше не обходится, поэтому:

- новые стартапы у нас не появляются вовсе;
- страницы каталога 5+ заморожены на 9 июля (данные настоящие, но не обновляются).

Сортировки по дате в API нет (`newest`/`created-desc` игнорируются), фильтр
`category` игнорируется. Значит «дай N самых новых» получить нельзя.

## Что API всё-таки даёт (проверено эмпирически)

- Сортировки по метрикам работают, включая **возрастание**: `revenue-desc/asc`,
  `growth-desc/asc`, `price-desc/asc`, `mrr-desc` (но не `mrr-asc`).
- `onSale=true` работает и честно рапортует `total: 200`.
- **Каждая сортировка — своё окно из 200.** Окна пересекаются лишь частично, поэтому
  их объединение даёт ~1000+ уникальных вместо 200.
- Детальный запрос по slug (`/api/v1/startups/{slug}`) потолком **не ограничен**.
- Списочный ответ содержит полный объект стартапа → отдельный detail-запрос
  новичку не нужен.

## Решение

Перевернуть источник правды: **`startup_archive` (Supabase, 8401 строка) —
источник, страницы Redis — производная витрина**, пересобираемая каждую ночь.
Это разом даёт новичкам куда «приземлиться», размораживает страницы 5+ и снимает
зависимость от 200-потолка.

### Ночной джоб, три фазы (~15 мин, 03:17 UTC)

**Фаза 0 — чтение архива.** Один тяжёлый постраничный `select=slug,data` (~9
запросов) в память: `Map(slug → data)`. Ключи этой карты = «что мы уже знаем»,
база для диффа.

**Фаза 1 — свод топ-200** (как сейчас, ~3 мин). `revenue-desc`, 20 upstream-страниц
по 10, детект зажима, ретрай 429. Обновляет записи в карте.

**Фаза 2 — детектор** (новое, ~10 мин). Пять окон `onSale=true`:
`revenue-desc`, `revenue-asc`, `price-desc`, `price-asc`, `growth-desc` — по 200
каждое, 100 запросов с паузой 7 с. Slug, которого не было в карте до начала
прогона, = **новый**. Данные берём прямо из ответа окна.
Побочная польза: заодно освежаются ~1000 листингов на продаже, а не только топ-200.

**Фаза 3 — запись и пересборка** (новое, ~2 мин, без API).
Апсерт освежённых в `startup_archive` + дневные снимки → затем из **полной**
карты: сортировка по `revenue.last30Days` desc → нарезка по 50 → ~168 страниц
Redis (`sm_page=N&limit=50&sort=revenue-desc` + флаги свежести), плюс точные
`sm_totals_v1` и `sm_sitemap_slugs` из всех 8401 (сейчас они пропускаются как
«урезанные»).

## Осознанные решения

**Пересобираем из ВСЕХ строк архива, включая снятые с TrustMRR.** Архив
insert-only, признака «жив» в нём нет. Использовать `last_seen` нельзя: мы больше
не обходим весь каталог, поэтому у большинства строк он навсегда застрял на
2026-07-09. Это не регресс — страницы 5+ и сегодня отдают тот же срез, а зомби
отсекает существующий `dropDead` (deny-list `dead_startups`) на чтении в
`api/startups.js`.

**Фронт трогать не нужно.** `catalog.html` ходит только за `sort=revenue-desc`
(`API_SORT`) и сортирует дальше у себя — пересобираем ровно один набор ключей.

**Только «на продаже».** Новичок вне продажи — не товар маркетплейса; выставится —
поймаем тем же прогоном. Полный веер окон (~240 запросов) отложен как неоправданный.

**Раз в сутки.** Квота 10/мин делится с живым сайтом и скрапером выручки; ночью
трафика мало. Новый листинг появляется максимум через сутки.

## Отказоустойчивость

- 429 → ожидание и повтор (не падение), как в текущем своде.
- Зажим (кусок без новых slug) → окно закрывается досрочно, не крутится до потолка.
- Фаза 3 не запускается, если карта заметно меньше прочитанного архива — лучше
  оставить вчерашние страницы, чем записать усечённый каталог.
- Каждая фаза независима: упавший детектор не мешает своду записать топ-200.
- Статус и число найденных новичков — в `sm_parser_catalog` → вкладка «Парсеры».

## Проверка

Моками (реальный API дёргать нельзя — квота): зажим на 200, 429 в середине,
пересечение окон, что новыми считаются только отсутствовавшие в архиве, и что
пересборка даёт непрерывный набор без дублей и потерь.
